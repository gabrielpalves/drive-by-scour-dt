# Drive-by Digital Twin for Railway-Bridge Scour

A physics-informed **Digital Twin (DT)** that monitors **scour** (and, later,
bearing/crack) damage on railway bridges from **drive-by** vibration — sensors on
the *passing train*, not on the structure. Two parts:

1. **Ablation study** *(Paper 1, complete)* — which neural architecture and which
   vehicle sensors best classify scour from drive-by signals.
2. **DT framework** *(Paper 2, in progress)* — evolve the bridge over its life
   (gradual + flood-shock scour), estimate its state each passage, and choose
   maintenance actions to minimise the expected **monetary** life-cycle cost
   (Value-of-SHM), with toggleable **risk perception**, **sensor health**, and a
   **major-flood decision branch** (probabilistic river-gauge trigger → probe /
   inspect / interrupt).

Everything is designed to be **toggled from one place** (`run_dt.py`) so scenarios
and methodologies can be switched on/off and compared. The
[toggle map](#toggle-map--what--where--how-to-verify) below says, for every
switch, *what it does*, *where it is implemented*, and *how to verify it*.

---

## Pipeline at a glance

```
 TTBI-2D physics  ──►  champion classifier  ──►  Bayes belief filter  ──►  planner  ──►  € cost
 (damaged bridge)      (PAA + N-HiTS, 2 DOF)     (transparent discrete)    (decision)    (Value-of-SHM)
        ▲                     ▲                          ▲                     ▲
        │              sensor health              risk perception        cost model
        └──── scour evolution (Kamariotis gradual + flood shock) ◄────────────┘
```

In production the classifier does **not** run live TTBI — it samples a pre-built
**held-out signal library** (`library` mode) generated by the MATLAB pipeline, so
the online loop is cheap and free of train/serve skew.

## How to run

```bash
# 1. Digital Twin — edit the CONFIG block in run_dt.py, then:
.venv/Scripts/python run_dt.py

# 2. Calibration (p_advance from the true scour model + fragility sweep):
.venv/Scripts/python -m digital_twin.calibrate

# 3. Ablation analysis (Paper 1 tables + figures):
.venv/Scripts/python plotting/aggregate_ablation.py

# 4. Conceptual figures for the framework (flood trigger + decision map; risk; value):
.venv/Scripts/python plotting/flood_decision_map.py       # -> results/flood_decision/
.venv/Scripts/python plotting/risk_perception_figure.py   # -> results/risk_perception/
.venv/Scripts/python plotting/flood_value_figure.py       # -> results/flood_value/
```

`run_dt.py` has three observation **modes**:

| `MODE` | Truth | Observation | Speed | Use |
|--------|-------|-------------|-------|-----|
| `mock` | `MultiScourModel` | banded confusion matrix | instant | develop/sanity-check policies |
| `library` | `MultiScourModel` | **real** held-out `.mat` signals + champion | fast | **production** Value-of-SHM (no skew) |
| `live` | `PhysicalAsset` (TTBI) | live passage + champion | ~min/passage | one-off end-to-end checks |

`library` mode needs a held-out dataset: generate it with `scour_MATLAB/A00_Run.m`,
move the run folder into `observations/<case>/`, and set `LIBRARY_DIR` to it
(see `observations/README.md`). The dataset must use the **same bridge geometry**
as the champion (40 m / 2-span / central-pier scour) or the classifier mispredicts.

## Toggle map — what · where · how to verify

Everything below is set in the `run_dt.py` CONFIG block unless noted. "Where" gives
the file + symbol; "verify" gives a concrete check.

### Bridge & damage — `TTBI_2D/damage_config.py`
- **What:** geometry (`configure_bridge`) and every damage type (`make_damage`:
  per-pier `scour_rates`, `bearing_rot_stiff`, `crack_locs/intensity`,
  `profile_intensity`). All default to healthy → a feature is "off" at its default.
- **Where:** `TTBI_2D/damage_config.py` (`configure_bridge`, `make_damage`).
- **Verify:** the legacy single-foundation 40 m scour-only bridge is reproduced
  exactly when only `scour_rates` is set on the central pier.

### Observation mode & models
- **What:** `MODE`, `CHAMPION_DIR`, `FALLBACK_DIRS`, `LIBRARY_DIR`.
- **Where:** wired in `digital_twin/harness.py` (`_library_setup`, `_live_setup`,
  `MockPhysical`); classifier in `digital_twin/assets.py` (`DigitalAsset.estimate_state`).
- **Verify:** `library` mode prints the loaded DOFs (`DOFs=['RearBogie_Vert',
  'CarBody_Pitch']`) and scores ~78 % exact / 98 % within ±1 on real `.mat`.

### Planner (decision methodology) — `PLANNERS`
- **What:** `do_nothing` baseline · `cost_vi` (cost-optimal MDP value iteration) ·
  `heuristic` (Kamariotis thresholds + inspect-after-flood) · `pomdp` (myopic
  Value-of-Information; the only one that *inspects* rationally) · `hybrid`
  (POMDP-inspect + cost-VI-repair).
- **Where:** `digital_twin/planner.py` (one class each); selected in
  `digital_twin/harness.py:build_planner`.
- **Verify:** the printed table ranks them by € life-cycle cost; `do_nothing` has by
  far the largest tail (`lifecycle_eur_cvar10`).

### Risk perception — `RISK_ATTITUDE`, `RISK_AVERSION`
- **What:** makes the belief-based planners (`pomdp`, `hybrid`) score the cost of a
  belief by a *risk measure* instead of the mean: `neutral` (= expectation, the
  baseline) · `cvar` (CVaR_α; `RISK_AVERSION`=α∈(0,1], smaller = more averse) ·
  `entropic` (exponential utility; `RISK_AVERSION`=θ≥0, larger = more averse). A
  risk-averse owner inspects more / repairs earlier.
- **Where:** `digital_twin/risk.py` (`RiskModel.perceived_cost`), threaded into
  `digital_twin/planner.py` (`POMDPPlanner._cost_do_nothing`). Sweep:
  `digital_twin/harness.py:sweep_risk` (set `SWEEP_RISK=True`).
- **Verify:** `SWEEP_RISK=True` → `vosh_risk_sweep.csv`: `n_inspect` climbs
  monotonically as aversion rises; `neutral` reproduces the baseline row exactly.

### Flood-decision branch — `FLOOD_BRANCH` (+ `FLOOD_SEVERITY_MAJOR`, `FLOOD_GAUGE_BETA`, `PROBE_SIGMA`, `N_PROBE`)
- **What:** on an observed **major** flood the asset owner runs a flood protocol
  *on top of* whatever routine planner is selected. A river gauge reads the flood
  severity with rating-curve noise; a **probabilistic** trigger
  `P(major | s) = Φ((ln s − ln s_major)/β_gauge)` (a hard threshold is the β→0
  limit) decides major vs minor. A major flood **widens the belief** by the
  uncertain scour shock, then the `FloodResponsePlanner` chooses
  **do_nothing / restrict_operations (a wider-confusion probe) / inspect /
  interrupt (close)** by risk-adjusted Value-of-Information — escalating to
  inspect if the probe is sensor-corrupted, and fusing `N_PROBE` probe passages.
- **Where:** `digital_twin/flood.py` (`FloodTrigger`, `widen_belief`),
  `digital_twin/planner.py:FloodResponsePlanner`, integrated in
  `digital_twin/simulation.py` (`DTSimulator._major_flood_step`); wired in
  `digital_twin/harness.py:run_comparison`. The probe confusion is the assumed
  wider `PROBE_SIGMA` banded matrix until a measured low-mass/low-speed MATLAB
  batch is supplied via `probe_dir`.
- **Verify:** `FLOOD_BRANCH=True` adds `n_major_flood`, `n_restrict`,
  `n_flood_inspect`, `n_interrupt`, `n_probe_escalated` columns;
  `plotting/flood_decision_map.py` renders the trigger CDF and the four-region
  decision map (and its shift under risk aversion / degraded sensors).

### Sensor health — `SENSOR_HEALTH` (+ `FALLBACK_DIRS`)
- **What:** drive-by sensors become fallible (WORKING/DEGRADED/DEAD; transient
  burst / degraded noise / dead-zeros; fault & noise scale carbody<bogie<wheel). A
  dead sensor falls back to the surviving single-DOF champion **and its wider
  confusion matrix**, so the belief automatically distrusts it; sensor maintenance
  is costed. All fault rates are **placeholders** in `SensorHealthParams`.
- **Where:** `digital_twin/sensor_health.py` (`SensorHealthModel`,
  `HealthAwareClassifier`); consumed in `digital_twin/simulation.py`
  (`DTSimulator.step`, the `(label, likelihood)` / `None` handling + `sensor_health`
  cost flush); built per-seed in `digital_twin/harness.py`.
- **Verify:** `SENSOR_HEALTH=True` adds `n_sensor_replace` and `n_blind_steps`
  columns to the output; `sensor_status` is logged per step in the history.

### Cost & fragility — `COST = CostModel(...)`
- **What:** verified Kamariotis € figures (`c_failure`, `c_inspect`, `c_repair`,
  `c_downtime_day`, `discount_rate`) + a **lognormal** fragility P(fail | scour) =
  Φ((ln s − ln θ)/β) (`fragility_median` θ, `fragility_beta` β — treat as a
  **swept assumption**; β≈0.05 brittle masonry … 0.3–0.4 deep piers).
- **Where:** `digital_twin/costs.py` (`CostModel`).
- **Verify:** `digital_twin/calibrate.py:fragility_sensitivity` sweeps the curve and
  shows the planner ranking is *not* robust to it (so we report it swept).

### Scour evolution & clock — `ENABLE_SHOCK`, `P_ADVANCE`, `DT_YEARS`, `N_STEPS`
- **What:** Kamariotis gradual deterioration + optional Compound-Poisson **flood
  shocks**; `P_ADVANCE` is the belief-filter deterioration prior; the clock is
  monthly by default (30 yr).
- **Where:** `digital_twin/assets.py:ScourModel.evolve`;
  `digital_twin/scour_multi.py` for correlated multi-foundation scour.
- **Verify:** `P_ADVANCE` is calibrated by `digital_twin/calibrate.py:estimate_p_advance`
  (≈ 0.007/month); flood steps are flagged in the history (`flood` column).

### Monitoring strategy
- **Routine** drive-by every step + the **flood branch** (`FLOOD_BRANCH`, above) for
  observed major floods are both implemented. The heuristic planner additionally
  carries scheduled / entropy inspect triggers. A standalone periodic-inspection
  toggle and the active-inference planner (Torzoni 2026) remain future work.

Every modelling choice — what we did, **why**, and the **references** that back it —
is recorded in **[docs/framework_rationale.md](docs/framework_rationale.md)**, kept
up to date as the framework evolves. It is the source for the paper's methodology

## Status & known limitations

- **Ablation (Paper 1):** complete and analysed.
- **DT framework:** the full loop runs and is validated in `mock` **and** `library`
  mode; planners, scour evolution (incl. floods), copula multi-foundation scour, €
  accounting, **risk perception**, and **sensor health** all work and are
  step-size-invariant. `neutral` risk + `SENSOR_HEALTH=False` reproduce the prior
  baseline exactly.
- **Train/serve skew (resolved):** the champion mispredicts on *live* re-simulated
  signals, so production uses `library` mode (held-out `.mat` from the training
  pipeline), where it scores ~78–79 % exact / ~100 % within ±1.
- **Sensor-health fault rates are placeholders** in `SensorHealthParams` — replace
  with vendor MTBF / field data; the model and wiring are final.
- **Risk perception:** with a cheap, sharp `inspect` available, risk-aversion buys
  *more monitoring* rather than fewer failures (the flood tail is largely
  irreducible by policy) — an honest Value-of-SHM finding, robust across observation
  noise. Without inspect, risk-aversion repairs earlier.
  (`plotting/risk_perception_figure.py`.)
- **Flood branch:** the major-flood decision branch is built and validated end-to-end
  (probabilistic trigger, belief widening, probe/inspect/interrupt by VoI, sensor-
  corruption escalation). The probe confusion is an **assumed** wider matrix until a
  measured low-mass/low-speed MATLAB batch is supplied (`probe_dir`); `s_major`,
  `β_gauge`, `probe_sigma`, and the exposure fraction are documented swept knobs.
- **Multi-damage:** the physics + scour generator support it; the decision loop is
  currently single-scour (61 classes) and will be extended once a multi-output
  classifier is trained at the longer bridge length.
